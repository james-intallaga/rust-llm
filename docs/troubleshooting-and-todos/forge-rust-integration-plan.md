## Executive Summary

This plan outlines the integration of a Rust layer into ForgeSDK to achieve memory-safe, efficient inference. The goal is to run Q8_0 models on iPhone 14 without OOM crashes.

## Part 2: Why Rust Solves the Memory Problem

### 2.1 RAII-Based Memory Management

Rust's ownership system **guarantees** cleanup through the `Drop` trait:

```rust
// In Rust, when LlamaModel goes out of scope, Drop is called automatically
impl Drop for LlamaModel {
    fn drop(&mut self) {
        unsafe {
            llama_free_model(self.model);  // ALWAYS called
        }
    }
}
```

In Swift, we had `llama_batch_free()` commented out and it went unnoticed. **This is impossible in Rust** - the compiler enforces cleanup.

### 2.2 Arena Allocators for Batch Memory

The Rust layer uses arena allocation patterns:

```rust
struct BatchArena {
    memory: Vec<u8>,
    offset: usize,
}

impl BatchArena {
    fn alloc(&mut self, size: usize) -> *mut u8 {
        let ptr = &mut self.memory[self.offset] as *mut u8;
        self.offset += size;
        ptr
    }

    fn reset(&mut self) {
        self.offset = 0;  // Instant "free" - no individual deallocations
    }
}
```

This eliminates fragmentation and provides O(1) cleanup.

### 2.3 Streaming Iterators vs Buffering

Instead of collecting all tokens in memory:

```rust
// Memory-efficient streaming
pub struct TokenStream<'a> {
    ctx: &'a LlamaContext,
    n_past: i32,
}

impl Iterator for TokenStream<'_> {
    type Item = Token;

    fn next(&mut self) -> Option<Token> {
        // Generate one token at a time
        // Memory freed automatically after each iteration
    }
}
```

### 2.4 Explicit Memory Budgets

```rust
pub struct InferenceConfig {
    pub max_memory_mb: usize,      // Hard limit
    pub batch_size: usize,          // Controlled allocation
    pub context_length: usize,      // KV cache size
}

impl InferenceEngine {
    pub fn new(config: InferenceConfig) -> Result<Self, MemoryError> {
        let estimated = Self::estimate_memory(&config);
        if estimated > config.max_memory_mb {
            return Err(MemoryError::WouldExceedBudget);
        }
        // ... proceed with allocation
    }
}
```

### Phase 2: Core Engine (Weeks 3-4)

**Goal:** Implement safe Rust wrappers with RAII

#### 2.1 Model Loading with Drop

```rust
// forge-core/src/model.rs
pub struct LlamaModel {
    ptr: *mut llama_model,
}

impl LlamaModel {
    pub fn load(path: &Path, params: ModelParams) -> Result<Self, ForgeError> {
        let c_path = CString::new(path.to_str().unwrap())?;
        let ptr = unsafe {
            llama_load_model_from_file(c_path.as_ptr(), params.into())
        };
        if ptr.is_null() {
            return Err(ForgeError::ModelLoadFailed);
        }
        Ok(Self { ptr })
    }
}

impl Drop for LlamaModel {
    fn drop(&mut self) {
        unsafe { llama_free_model(self.ptr); }
    }
}
```

#### 2.2 Context with Batch Arena

```rust
// forge-core/src/context.rs
pub struct LlamaContext {
    ptr: *mut llama_context,
    batch: BatchArena,
}

impl LlamaContext {
    pub fn new(model: &LlamaModel, params: ContextParams) -> Result<Self, ForgeError> {
        let ptr = unsafe {
            llama_new_context_with_model(model.ptr, params.into())
        };
        let batch = BatchArena::new(params.n_batch as usize);
        Ok(Self { ptr, batch })
    }
}

impl Drop for LlamaContext {
    fn drop(&mut self) {
        // Batch arena freed automatically via Vec<u8>
        unsafe { llama_free(self.ptr); }
    }
}
```

## Part 5: Risks and Mitigations

### 5.1 Risk: bindgen Compatibility

**Risk:** llama.cpp headers may have C++ constructs that bindgen can't handle.
**Mitigation:** Use the existing C-compatible headers in `llama.xcframework`. Create minimal wrapper headers if needed.

### 5.2 Risk: Metal Shader Compilation

**Risk:** Rust layer may interfere with Metal shader loading.
**Mitigation:** Keep llama.cpp as the pre-built xcframework; Rust only wraps the C API.

### 5.3 Risk: UniFFI vs cbindgen Choice

**Risk:** UniFFI may add overhead; cbindgen requires manual Swift wrappers.
**Mitigation:** Start with cbindgen for full control. UniFFI can be added later for convenience.

## Appendix: Key Learnings from llama-cpp-rs

1. **RAII everywhere:** Every C pointer wrapped in a struct with `Drop`
2. **No raw pointers in public API:** All handles are opaque types
3. **Batch reuse:** Pre-allocated batch buffers, reset between inferences
4. **Error handling:** All C errors converted to Rust `Result` types
5. **Thread safety:** `Send + Sync` bounds where appropriate
