# forge-rust: Rust Core for Forge SDK

A memory-safe Rust wrapper for llama.cpp, providing RAII-based memory management for iOS/macOS inference.

## Architecture

```
forge-rust/
├── Cargo.toml              # Workspace definition
├── forge-core/             # Safe Rust API
│   ├── src/
│   │   ├── lib.rs          # Main module exports
│   │   ├── engine.rs       # High-level ForgeEngine API
│   │   ├── model.rs        # Model loading with Drop
│   │   ├── context.rs      # Context management with RAII
│   │   ├── batch.rs        # Arena-style batch allocator
│   │   ├── sampler.rs      # Full sampler chain
│   │   ├── multimodal.rs   # Vision/CLIP support (mtmd API)
│   │   ├── memory.rs       # Memory tracking
│   │   ├── error.rs        # Error types
│   │   └── ffi.rs          # C FFI for Swift interop
│   ├── build.rs            # cbindgen for header generation
│   └── cbindgen.toml       # Header generation config
├── llama-cpp-sys/          # Low-level FFI bindings
│   ├── src/
│   │   └── lib.rs          # Type stubs and function declarations
│   └── build.rs            # bindgen for auto-generation
├── include/                # Generated C headers
│   └── forge_ffi.h         # Auto-generated by cbindgen
└── scripts/
    ├── build-ios.sh        # Build for iOS targets
    └── package-xcframework.sh  # Create XCFramework
```

## Key Features

### 1. RAII Memory Management

All C resources are wrapped with Rust's `Drop` trait for guaranteed cleanup:

```rust
impl Drop for LlamaModel {
    fn drop(&mut self) {
        unsafe { llama_free_model(self.ptr); }  // ALWAYS called
    }
}
```

### 2. Full Sampler Chain

Complete sampling pipeline matching llama.cpp's capabilities:
- Repetition/presence/frequency penalties
- DRY (Don't Repeat Yourself) sampler
- Top-K, Top-P, Min-P filtering
- Temperature scaling
- Distribution sampling

### 3. Context Window Sliding

Automatic handling of long conversations:
- Preserves system prompt tokens
- Shifts context when approaching limit
- Transparent to the caller

### 4. Device Auto-Detection

Optimal configuration based on device capabilities (handled in ForgeSwift layer).

## Building

### Prerequisites

1. Rust toolchain (stable)
2. iOS targets installed:
   ```bash
   rustup target add aarch64-apple-ios aarch64-apple-ios-sim x86_64-apple-ios
   ```
3. Xcode with iOS SDK
4. Pre-built `llama.xcframework` in the repo root

### Build Steps

```bash
# 1. Check that code compiles
cd forge-rust
cargo check

# 2. Build for iOS
./scripts/build-ios.sh

# 3. Package into XCFramework
./scripts/package-xcframework.sh

# 4. Copy to ForgeSwift
cp -R build/ForgeRustCore.xcframework ../ForgeSwift/
```

## C API (for Swift)

The FFI module exposes a C-compatible API:

```c
// Initialize
forge_init();

// Create engine
ForgeParams params = forge_params_default();
params.n_ctx = 2048;
params.n_batch = 128;
ForgeHandle engine = forge_engine_create_vision(model_path, clip_path, &params);

// Generate with streaming
forge_generate_vision(engine, image_data, image_len, prompt, callback, user_data);

// Cleanup
forge_engine_destroy(engine);
forge_cleanup();
```

## Why Rust?

1. **Guaranteed cleanup**: Rust's ownership system ensures resources are freed
2. **No reference counting bugs**: Unlike Swift ARC with C pointers
3. **Zero-cost abstractions**: RAII patterns compile to the same code as manual cleanup
4. **Memory safety**: Buffer overflows and use-after-free are compile-time errors
